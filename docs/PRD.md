# 融网学习平台产品需求基线

基线日期：2026-11-11。Q1、Q2、Q3、Q4、Q5、Q6、Q7、Q9、Q10、Q13 的下述业务规则全部已确认。剩余事项单列于 [OPEN_QUESTIONS](OPEN_QUESTIONS.md)。

## 1. 定位、用户与范围
面向课程教学的在线学习与练习管理 Web 平台。教师创建课程、维护题库、发布任务；学生加入课程、作答、查看成绩、复练错题。闭环为发布任务 → 在线作答 → 后端判分 → 错题归集 → 复练 → 更新掌握状态。
第一版支持单选、多选、判断题，不包含直播、视频课程、付费、主观题阅卷、排行榜、审批入课或微服务。
前端：Vue 3、TypeScript、Vite、Element Plus、Vue Router、Pinia、Axios。后端：Java、Spring Boot、Spring MVC、MyBatis-Plus、Maven；数据库 MySQL。架构为前后端分离、RESTful API、单体应用。

## 2. 账号与权限（Q1）
教师和学生账号均由平台维护者预先创建，一个账号固定一个角色，不开放自助注册。支持启用、禁用；禁用账号不能登录；密码必须安全哈希存储，不保存明文或可逆密码。
教师只能管理自己创建的课程及其题库和任务；学生只能访问已加入课程及本人答卷、错题。每个受保护请求由后端验证身份、角色、资源归属，不能只靠前端隐藏入口。
账号创建的操作界面或工具、认证方案属于工程设计事项，不默认采用 Session 或新增管理端产品。

## 3. 课程、题库与加入流程（Q5、Q13）
每门课程拥有独立题库，不同课程不能直接共用原始题目，任务只能选择所属课程题库题目。教师进入“我的课程 → 题库”查询、新增、编辑单选、多选、判断题，维护题干、选项、标准答案、分值和解析。
教师在课程详情分享邀请码；学生登录后进入“我的课程 → 加入课程”，输入有效邀请码。后端验证当前学生身份、邀请码及课程状态后直接加入，无需审批。重复加入返回已有成员关系，不新建重复记录。
邀请码默认不自动过期；教师可手动重置，旧码立即失效，已加入成员不受影响。课程归档后邀请码失效；如何归档及其他归档影响仍属 Q8，不能据此推定归档后禁止复练等额外规则。

## 4. 任务发布与快照（Q6）
草稿允许编辑名称、说明、截止时间、选题与顺序。发布时保存独立完整题目快照，包括题型、题干、选项、标准答案、解析、分值及题目顺序。
题库原题存于 `question`，任务信息存于 `task`，任务题目完整副本存于 `task_question`。后端判分与历史查看读取任务快照，不能实时套用题库新答案。
发布后完全锁定：不得修改任务信息、题目、选项、答案、解析、分值、顺序和截止时间，不得撤回。发现错误，复制任务为新草稿，修改后重新发布，原任务和历史保持不变。复制保留同课程原题来源，形成独立新任务快照，不复制学生答卷和成绩。
例如原题答案 A、C 发布至任务 T1 后，题库改为 A、D，T1 仍按 A、C 判分。

## 5. 提交、截止与答案公开（Q2、Q3、Q4）
截止前允许不限次数正式提交，每次成功提交保留独立答卷及逐题记录。最终成绩为该学生该任务历史最高分；最高分并列时取最后一次获得最高分的答卷作为统计代表。之后的低分不降低最终成绩，也不替换最高分代表答卷。
服务器首次收到新请求的时间必须严格早于截止时间；等于或晚于截止均拒绝。学生提前点击但网络晚到也拒绝；客户端时间无效。工程实现必须保存请求进入服务器时的可信时间，不能使用判分结束时间替代。
处理顺序：验证当前身份与权限 → 查找已成功幂等记录并核对任务及请求内容 → 命中返回原结果 → 未命中才按首次接收时间校验截止并判分。已成功同键请求截止后仍可返回；同键不同内容冲突，不得泄露其他用户记录。同键并发只能形成一份成功答卷，不能重复累加错题。
首次成功提交前不得返回标准答案和解析；成功后立即公开本次答卷的答案与解析。重交正常判分并保存历史，重新打开作答页不代表此前公开的答案恢复保密。

## 6. 判分与精度（Q7）
允许漏答：未作答为零分，保存空答案逐题记录，并进入个人错题本。未知或重复选项、其他任务题目等非法参数拒绝整次提交，不能当普通答错处理。
分值必须大于零，最多两位小数；MySQL 使用 DECIMAL(8,2)，Java 使用 BigDecimal，禁止浮点数判分或默默截断超过两位的小数。总分须在存储字段可表示范围内。
单选和判断题匹配标准答案才得满分。多选至少两个正确选项，按集合完全匹配：顺序无关，少选、多选、错选零分；重复或未知选项拒绝。所有标准答案与分值取自任务快照。

| 标准答案 A、C，分值 4 | 结果 |
|---|---|
| A、C 或 C、A | 4 分 |
| A / A、B、C / B、D | 0 分 |
| 空答案 | 0 分，记录错题 |
| A、A、C 或未知选项 | 整次提交拒绝，不写答卷或增加错题 |

## 7. 错题状态与历史（Q9）
错题以“学生 ID + 原始题目 ID”唯一；跨任务使用同一原题也只有一条错题主记录。保留错误次数、最近错误时间、掌握状态及全部正式答题和复练历史。

| 事件 | 错误次数 | 掌握状态 |
|---|---|---|
| 首次正式答错（含漏答） | 新建为 1 | 未掌握 |
| 再次正式答错 | 加 1 | 恢复未掌握 |
| 正式答对（含重交） | 不变 | 不自动改变；无错题也不新建 |
| 错题复练答错 | 加 1 | 恢复未掌握 |
| 错题复练答对 | 不变 | 自动已掌握 |
| 手动标记或取消掌握 | 不变 | 设置为已掌握或未掌握 |
| 同一成功幂等请求重试 | 不变 | 不重复执行状态更新 |

正式提交、逐题记录和错题更新必须在同一事务中成功或回滚。复练记录与错题更新同样保持事务一致，复练不修改正式成绩。答对或手动标记不得删除历史，也不清零错误次数。
学生按课程和掌握状态筛选错题并进入复练。历史始终展示当次快照。复练选用最近答错快照作为工程设计建议，不能据此改变已确认状态规则。

## 8. 教师统计（Q10）
本期按课程统计班级数据。每个已提交学生选一份最高分代表答卷，最高分并列选择最后一次取得最高分者。最高分是数值，代表答卷是具体记录，二者不能混淆。

| 指标 | 统一口径 |
|---|---|
| 提交率 | 已提交学生人数 / 统计时当前课程成员人数 × 100%；后来加入者计入分母 |
| 班级平均分 | 已提交学生各自历史最高分之和 / 已提交学生人数 |
| 班级正确率 | 代表答卷正确题目总数 /（已提交学生人数 × 任务题目总数）× 100% |
| 逐题正确率 | 代表答卷该题答对人数 / 已提交学生人数 × 100% |

未提交学生不参与平均分和正确率；漏答计入题数分母并按错误处理；复练不参与；重交不重复统计人数。零分的成功提交属于已提交，不能当未提交。
无人提交时平均分、正确率为空值并显示“暂无数据”；成员数大于零时提交率为 0%；成员数为零时提交率为空值，避免除零。这是显示约定，不改变统计公式。

## 9. 异常、验收与范围边界
无效邀请码、越权、非法选项、截止拒绝均不生成半份业务数据。新请求失败后不视为成功幂等记录；事务回滚后可重新请求，但仍遵循新请求接收时间的截止校验。
核心验收案例见 [开发计划](DEVELOPMENT_PLAN.md)。Q8 生命周期、Q11 部署容量、Q12 自动保存以及 Q1 操作方式与认证方案保持开放，不能作为已经实现或已定案的规则。下一阶段仅开展经负责人确认的 UI 原型设计。
