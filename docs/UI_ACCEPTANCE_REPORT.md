## 9. 返回导航专项修复与回归

### 9.1 问题及改动
产品负责人反馈：完整教学闭环可以操作，但部分子页面缺少返回上级入口。源码确认此前页面切换只替换视图，没有统一历史记录，且 navigate 会清空搜索，因此仅增加装饰按钮不能满足需求。

本次修改：
1. 子页面和弹窗顶部左侧使用同一 back-button，包含左箭头及“返回课程列表/任务详情/历史成绩”等明确文字。登录和课程工作台不增加多余返回按钮；列表级主导航保持简洁。
2. 引入本次打开期间的页面记录，优先返回同角色下有效的实际来源；不存在有效来源时使用下方默认路径。历史记录指向不存在资源、已截止答题或不适合当前角色的页面时，跳过或降级至有效列表/详情。
3. 页面跳转使用 History API 的 pushState/replaceState，popstate 恢复页面状态；题号定位改为页内滚动按钮，避免题号锚点污染页面历史。
4. 记录课程、题库搜索、错题课程/状态筛选、历史任务筛选、表单输入及滚动位置。题目编辑与预览弹窗作为导航层记录，返回或 Escape 关闭到来源，前进可恢复尚未提交的表单。
5. 未提交答题或复练答案离开时使用浏览器原生确认框；取消停留当前页面并保留勾选。确认后丢弃当前未提交答案，历史记录中的相应勾选同步清除，前进不会悄悄恢复已丢弃答案。已成功提交记录不受影响。
6. 侧栏导航、返回按钮和浏览器后退均应用离开保护；取消浏览器后退时恢复原历史位置。刷新/关闭页面使用 beforeunload 的浏览器标准提示机制（显示受浏览器策略约束，未实测）。
7. 表单草稿仅在本次打开期间保留；不使用本地持久化，不把 Q12 自动保存机制擅自定案。刷新仍会重置虚构业务数据；失效资源地址会安全落到列表或详情。
