# 第二阶段 UI 原型 V1

## 1. 交付与打开方式
产品负责人已授权进入 UI 原型阶段。入口为 [prototype/index.html](../prototype/index.html)，在资源管理器中双击即可用浏览器打开，不需要安装依赖、启动后端或初始化工程。
演示账号：教师 `teacher`、学生 `student`，密码均为 `123456`；`disabled` 演示禁用账号。也可使用“教师快速演示”“学生快速演示”。这些是公开的虚构原型数据，不是真实凭据。
页面顶部有评审专用角色切换、截止场景切换及原型说明；它们不是正式产品的权限入口。刷新清空演示数据，不能视为已经确定自动保存方案。

## 2. 视觉与布局
- 风格：教学管理工作台，深青侧栏、浅色内容区域、蓝绿色主操作，少量橙色提示待办。
- 导航：教师以课程、任务、题库为主；学生以课程、任务、提交记录、错题为主。
- 信息层级：页面标题 → 关键操作 → 概览/筛选 → 表格或题目内容。主按钮用于创建、发布、提交和复练。
- 表格展现题库、任务、成绩和历史；卡片展现课程与关键统计；表单、确认弹窗控制创建和发布。
- 桌面优先，窄屏下侧栏改为顶部横向导航、双栏作答区域堆叠；响应式实际效果仍需浏览器验收。
- 绿色和橙色状态均有文字说明，不只靠颜色区分；输入具有标签和可见焦点，提示使用可访问状态区域。

## 3. 页面与功能覆盖
| 页面组 | 已制作的原型状态 |
|---|---|
| 登录 | 账号密码、错误账号/密码、禁用提示、双端演示入口，无注册 |
| 教师课程 | 课程卡片、新建/编辑表单、概览、成员列表、邀请码重置确认 |
| 教师题库 | 按课程切换、关键词搜索、新增/编辑、三种题型、答案选择及正分值校验 |
| 教师任务 | 任务列表、草稿、题库选题、排序、移除、编辑独立副本、发布确认 |
| 已发布任务 | 只读快照、统计入口、复制新任务；没有延期、撤回或原地编辑 |
| 教师统计 | 当前成员提交率、已提交学生最高分平均值、代表答卷正确率、逐题正确率 |
| 学生课程 | 已加入列表、邀请码加入、无效码和重复加入提示 |
| 学生任务 | 详情、作答导航、未答数量、漏答提交确认、截止状态 |
| 成绩与历史 | 本次分数、最高分、代表答卷、逐题解析、历次提交、重新作答 |
| 错题 | 按课程和掌握状态筛选、详情、错误次数、最近错误时间、复练历史 |
| 复练 | 正确自动掌握、错误恢复未掌握；手动标记和取消掌握 |

创建/编辑、邀请、发布和提交确认使用可复用弹窗，不为每个操作建立独立文件。当前为单页内存原型，不代表已经实现 Vue Router 路由或后端 API。

## 4. 推荐评审路径
### 教师流程
1. 教师快速演示 → Java 程序设计 → 邀请码重置，检查旧码失效、成员保留的提示。
2. 课程题库 → 新增单选、多选或判断题 → 检查题干、选项、答案、分值和解析。
3. 练习任务 → 编辑草稿 → 选题、调整顺序和编辑副本 → 保存 → 预览并发布。
4. 已发布任务 → 检查只读内容 → 复制新任务 → 修改副本，原任务不变。
5. 查看统计，检查最高分、代表答卷和三项指标的呈现是否清楚。

### 学生流程
1. 学生快速演示 → 加入课程；默认 `JAVA2026` 已加入，`MYSQL2026` 可加入。教师重置过的旧码不能使用。
2. Java 任务 → 开始作答 → 故意漏答或答错 → 提交后查看答案、解析与错题。
3. 再练一次 → 更换答案 → 提交，检查最高分不会被低分覆盖，并列取最后一份代表。
4. 我的错题 → 筛选 → 详情 → 复练，检查正确自动掌握、错误次数累加。
5. 手动取消掌握，再正式作业答对，检查错题状态保持不变。
6. 顶部切换“演示截止场景”，检查新的作答/提交入口和拒绝提示。

## 5. 数据与生产实现边界
原型为纯本地虚构数据。为了展示反馈，标准答案与模拟判分逻辑存在 HTML 中；这不满足生产“后端保密和判分”要求，不能直接作为业务实现使用。正式项目必须采用后端鉴权、可信服务器接收时间、数据库幂等约束与事务，并从任务快照判分。
本原型不验证真实并发、网络重试、事务回滚、服务器截止、密码哈希或持久化。仅初始 Java 任务具有李同学的固定统计示例；新建/复制任务没有虚构提交。陈同学成绩随演示提交变化，成员分母按当前课程的演示加入状态计算；没有伪称真实教学数据。
任务与题库在内存中复制隔离，用于验证交互含义，不代表数据库分表已经实现。演示题型编辑器提供四个选项、判断题两个选项，这是当前展示模板，不冻结实际系统的选项数量上限。

## 6. 未决项与后续评审
Q8 删除/退出/归档策略、Q11 部署容量、Q12 自动保存/恢复、账号维护操作与认证方案保持未决。原型未提供已定案的删除、退课、归档或恢复功能。
请优先评审：导航是否容易理解、教师组卷是否顺手、本次成绩与最高分区分是否明显、错题状态反馈是否清楚。视觉或交互意见只影响第二阶段设计，不自动变更冻结业务规则。
